# 医院叙事生成助手 — 产品优化方案（第一至四模块）

> 版本：v1.0  
> 本文档汇总系统产品化为医生服务的前四个核心设计模块：定位、产品形态、功能优化、用户体验。

---

## 一、产品定位与目标用户

### 1.1 产品定位

**"科室智能叙事助手"** —— 不替代医生决策，而是把分散的医疗数据转化为医生可快速理解、可信任的叙事和洞察。

### 1.2 分层用户

| 用户层级 | 角色 | 核心需求 | 产品形态 |
|----------|------|----------|----------|
| **一线医生** | 住院医师、主治医师 | 快速了解患者全貌、写病历/交接班、查房汇报 | 患者时间线、智能病程小结、诊疗路径参考 |
| **科主任/质控员** | 科室管理者 | 科室运营、质控指标、质量改进 | 科室运营简报、质控异常报告、周/月报 |
| **医务部/院领导** | 医院管理层 | 跨科室对比、资源调配、风险预警 | 院长驾驶舱、跨科对比、风险患者清单 |
| **科研人员** | 临床研究者 | 病种规律、真实世界研究 | 数据导出、队列筛选、统计摘要 |

### 1.3 产品形态演进

```
当前状态                    产品化演进
─────────────────────────────────────────────────────────
Web端（Streamlit）    →     Web端 + 微信小程序/钉钉应用
被动查询              →     主动推送（每日晨会简报）
单次分析              →     患者全程跟踪（入院→出院→随访）
通用报表              →     角色化视图（医生/主任/院领导）
```

## 二、核心产品形态设计

### 2.1 推荐产品模块

| 模块 | 功能 | 价值 |
|------|------|------|
| **患者全息视图** | 整合历次就诊、诊断、用药、检查、手术时间线 | 医生 3 分钟掌握患者全貌 |
| **智能病程小结** | 基于本次入院数据自动生成病程记录/出院小结草稿 | 减少文书工作 30-50% |
| **查房问答助手** | 语音/文字提问："该患者为什么再入院风险高？" | 查房场景即时辅助 |
| **科室晨会简报** | 每日自动推送：新入院、重点关注、手术、质控异常 | 提升晨会效率 |
| **质控闭环管理** | 异常识别 → 推送责任医生 → 整改记录 → 效果追踪 | 从发现到改进闭环 |
| **诊疗路径推荐** | 基于相似患者和指南推荐检查/用药/手术方案 | 辅助规范化诊疗 |
| **科研队列工具** | 按病种/时间/指标筛选患者，导出脱敏数据集 | 支持真实世界研究 |

## 三、功能优化方向

### 3.1 患者故事线 → 患者全息视图

当前功能：输入患者ID生成故事线。

产品化升级：
- **时间轴可视化**：按就诊、检查、用药、手术分层展示
- **关键事件标记**：化疗周期、手术、不良反应、再入院
- **一键生成病程摘要**：按 SOAP 格式（主观/客观/评估/计划）
- **异常高亮**：自动标出住院天数异常、缺失检查、药物相互作用

### 3.2 报告生成 → 角色化智能简报

当前功能：生成科室运营简报和周简报。

产品化升级：

| 角色 | 简报内容 |
|------|----------|
| 住院医 | 今日管床患者重点、待办事项 |
| 主任 | 科室本周运营、质控问题、重点关注患者 |
| 院领导 | 全院多科室对比、关键质量指标趋势 |
| 质控员 | 异常事件清单、整改进度 |

### 3.3 知识图谱叙事 → 临床决策参考

当前功能：基于图谱生成叙事。

产品化升级：
- **相似患者推荐**："该患者与 5 例相似患者的治疗方案对比"
- **诊疗路径偏离提醒**："当前患者未按常规路径完成术前检查"
- **药物相互作用预警**：实时校验当前处方
- **再入院风险评分**：入院时自动评估并提示

### 3.4 RAG问答 → 查房智能助手

当前功能：基于图谱回答问题。

产品化升级：
- **语音输入**：支持医生语音提问
- **多轮对话**：追问和上下文理解
- **答案溯源**：每个结论都标注数据来源（病历号、检查单号）
- **不确定性提示**：当证据不足时明确告知"数据不支持"

## 四、用户体验（UX）优化

### 4.1 交互设计

| 当前问题 | 优化方向 |
|----------|----------|
| 页面较多（17个） | 按角色和使用场景重组导航 |
| 需要手动输入ID | 扫码/选择患者自动带入 |
| 报告生成等待时间长 | 异步生成 + 结果通知 |
| 图表与文本分离 | 患者时间轴图文混排 |

### 4.2 移动端适配

医生大量使用移动场景：
- **微信小程序/企业微信**：查看晨会简报、接收预警
- **iPad 查房端**：患者全息视图、语音问答
- **PC 办公端**：深度报告、科研分析

### 4.3 推送与提醒

- 每日 7:30 推送科室晨会简报
- 患者再入院风险评分 > 70 分时推送主管医生
- 质控异常事件实时推送质控员
- 周/月报定时生成并推送给科主任

## 五、前端设计总原则

基于以上四个模块的优化方向，前端设计应遵循以下原则：

1. **以医生工作流为中心**：减少点击次数，核心信息一眼可见
2. **角色化首页**：不同角色登录后看到不同的默认仪表盘
3. **卡片式布局**：信息模块化，支持快速扫描
4. **视觉层级清晰**：重要信息突出，辅助信息弱化
5. **移动端优先**：关键功能在手机上可用
6. **医疗专业感**：蓝白配色、清晰字体、充足留白
7. **即时反馈**：加载状态、操作结果明确提示
