医院叙事生成助手
前端功能与技术点演进文档
（从 Streamlit 迁移至 React 前端至今）

生成时间：2026-06-22 17:15


一、前言
医院叙事生成助手是一个基于大语言模型（LLM）与 Neo4j 医疗知识图谱双引擎驱动的医院科室历史数据智能分析与叙事生成平台。项目早期使用 Streamlit 构建快速原型页面，随着功能复杂度和交互体验要求的提升，团队决定放弃 Streamlit 导航式页面，重新构建一套基于 React + Vite + Ant Design + ECharts 的现代化单页应用（SPA）前端。
本文档系统梳理了从 Streamlit 前端迁移/重建开始，到目前为止（2026 年 6 月）所有主要功能迭代、技术点改造与问题修复，供团队复盘、交接与后续维护参考。
二、前端架构演进
2.1 技术栈选型
新前端采用以下技术栈：
React 18：组件化 UI 框架
Vite：下一代前端构建工具，提供极速的 HMR 与构建体验
React Router v6：前端路由管理
Ant Design 5：企业级 UI 组件库
Ant Design Icons：图标库
ECharts 5 + echarts-for-react：数据可视化
echarts-wordcloud：词云图扩展
Axios：HTTP 请求库
Zustand（通过 stores/auth.jsx）：轻量级状态管理，用于认证与权限
Day.js：日期处理
2.2 项目结构
frontend/ 目录结构如下：
src/views/portal/：医生前台视图（工作台、患者全息视图、查房助手、晨会简报、相似患者/诊疗路径、质控闭环管理、科研队列等）
src/views/admin/：后台管理视图（用户管理、角色权限、功能开关、系统配置、缓存管理、概览仪表盘）
src/layouts/：PortalLayout（医生前台布局）与 AdminLayout（后台管理布局）
src/api/index.js：统一封装的 Axios 请求
src/components/：可复用组件，如 PatientSearch、PatientIdLink
src/stores/auth.jsx：认证状态与权限/功能开关管理
src/router/index.jsx：前端路由配置
三、功能模块演进
3.1 医生前台（Portal）
3.1.1 工作台
登录后默认首页，展示系统入口与简要说明
顶部导航菜单根据用户角色与功能开关动态渲染
3.1.2 患者全息视图（PatientDetailView）
患者全息视图是前台的核心模块之一，经历了多轮优化：
图文时间轴精简：从最初的完整就诊列表，精简为只展示关键事件（手术、检查），避免数据量大时页面冗长。
就诊概览卡片：新增按次就诊的卡片式概览，展示日期、住院天数、主诉、诊断、手术/用药/检查数量。
住院趋势图：使用 ECharts 折线图展示历次住院天数。
住院情况概览（最新）：将关键事件时间轴与住院趋势图合二为一，折线图 X 轴以第一次住院为起点，并在折线上用 markPoint 标记每次住院的检查/检验数量，tooltip 固定宽度、鼠标右侧显示。
就诊概览词云图（最新）：将卡片列表替换为“诊断词云”和“用药词云”两张 ECharts 词云图，直观展示高频诊断与用药。
关键异常提示：基于风险评分、质控问题、住院天数、化疗/手术史、再入院次数等生成异常标签。
智能病程摘要：展示基于知识图谱生成的患者完整叙事。
风险预测与质控：展示风险等级、风险评分、风险因素及质控问题列表。
再入院分析： originally 与相似患者合并展示，后拆分为独立 Card，并去除 200 字截断，默认完整展示，超长时滚动。
相似患者：展示 Top 5 相似患者及相似度。
患者 ID 链接组件化：所有患者 ID 均使用 PatientIdLink 组件，点击可跳转至全息视图。
3.1.3 查房助手（WardRoundView）
支持选择患者后基于知识图谱 RAG 回答医疗问题
修复了 RAG 问答中患者 ID 识别问题：KGRAGRequest 增加 patient_id 字段，后端优先使用传入 patient_id，而非依赖文本解析
可基于真实就诊记录回答，例如 51 次就诊的患者
3.1.4 科室晨会简报（BriefingView）
修复初始化日期问题：直接使用模拟日期加载，避免 setDate 异步导致首次渲染为空
支持按日期查询每日简报
根据角色权限展示科室选择器
3.1.5 相似患者 / 诊疗路径（SimilarPatientView）
相似患者推荐：输入患者 ID 后查找相似病例，展示相似度、共同诊断、共同用药
修复相似度显示 NaN% 的问题：前端表格 dataIndex 由 similarity 改为后端返回的 score
优化患者搜索框宽度：PatientSearch 组件默认占满 100% 宽度，与诊疗路径推荐的 Input 样式保持一致
诊疗路径推荐：输入疾病名称后生成诊疗路径叙事与关键数据
3.1.6 质控闭环管理（QualityView）
三个 Tab：今日质控异常、患者质控问题、整改追踪
修复字段名不匹配：将 briefing.quality_issues 改为 briefing.quality_control_issues
修复患者质控问题不显示：后端 issues 为数组，前端原按对象遍历导致为空，改为直接遍历数组
选择患者后自动触发查询
操作列仅对 admin / department_manager / quality_controller 开放，可修改整改状态
3.1.7 科研队列
支持按疾病、用药、检查等条件筛选患者队列
患者 ID 使用 PatientIdLink 组件
3.2 后台管理（Admin）
用户管理：新增/编辑/删除用户，支持角色分配
角色权限管理：新增角色权限编辑页面，支持 9 角色体系
功能开关：动态控制前台菜单与功能是否展示
系统配置：包含模拟日期等配置
缓存管理：展示 LLM 缓存统计，支持清理缓存
后台概览仪表盘：展示知识图谱统计、LLM 缓存统计、系统状态
修复后台概览页 KG 节点/关系数为 0 的问题：前端适配后端返回的 nodes/relationships 结构
修复 LLM 缓存无条目显示问题：前端读取 cacheStats.stats 字段
四、关键技术点与后端改造
4.1 角色权限与功能开关体系
建立了 9 角色体系：admin、department_manager、hospital_manager、quality_controller、attending_doctor、resident_doctor、director、researcher、viewer。菜单根据 permissions 数组与 features 功能开关动态渲染。
4.2 认证体系
后端使用 bcrypt 加密密码、PyJWT 签发 Token
前端使用 localStorage 存储 token，Axios 请求头携带 Authorization
后台路由单独鉴权
4.3 LLM 缓存机制
database/llm_cache.py 实现基于文件系统的 LLM 输出缓存
缓存键基于 namespace + 内容哈希，避免重复调用 LLM
支持 TTL（默认 240 小时）、过期自动清理、按命名空间清理
llm_service.chat 自动读取/写入缓存
4.4 结果缓存机制（新增）
新增 database/result_cache.py 通用结果缓存模块
为风险预测、相似患者、再入院患者叙事等服务添加完整结果缓存
显著降低患者全息视图加载时间：相似患者从 10 秒级降至 10 毫秒级
4.5 MySQLClient 修复
修复 INSERT/UPDATE/DELETE 不支持 lastrowid 的问题
修复用户 CRUD 和角色权限更新 500 错误
4.6 依赖补充
pyproject.toml 补充 bcrypt、PyJWT、openpyxl
前端补充 echarts-wordcloud
4.7 模拟日期配置
config.py 新增 simulation_date 配置，用于测试环境固定日期
每日简报默认使用模拟日期，避免首次渲染为空
五、重点问题修复记录
5.1 前端显示类
后台概览页 KG 统计为 0：前端字段名不匹配，已适配
后台概览页 LLM 缓存无条目：前端未取 stats 嵌套字段，已修复
相似患者相似度 NaN%：前端使用 similarity 字段而后端返回 score，已统一
再入院分析 500：readmission_service.py 漏引入 result_cache_store，已补充 import
质控闭环管理无数据：字段名 quality_issues 与 quality_control_issues 不匹配，已修复
患者质控问题不显示：前端将数组误按对象遍历，已修正
再入院叙事截断：原代码手动 slice(0,200)，已改为完整展示
5.2 性能优化类
患者全息视图三个板块（风险预测、再入院、相似患者）添加结果缓存，二次加载从秒级降至毫秒级
质控、再入院、风险预测等服务均接入 LLM 缓存
5.3 交互优化类
患者全息视图时间轴与住院趋势合并为“住院情况概览”
就诊概览改为诊断/用药词云
再入院分析与相似患者拆分为两个独立区域
智能病程摘要与再入院分析固定等高 520px，默认展开
PatientSearch 搜索框默认占满宽度
