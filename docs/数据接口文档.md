# 医院叙事生成助手 — 数据方接口文档

> 版本：v1.0  
> 用途：指导数据方开发/暴露数据接口，供医院叙事生成助手调用并正常运行。

---

## 一、接口总体说明

### 1.1 通信协议
- **协议**：HTTPS（生产环境必须）或 HTTP（测试环境）
- **数据格式**：JSON
- **字符编码**：UTF-8
- **Content-Type**：`application/json`

### 1.2 认证方式（任选其一，需在对接时确认）

| 方案 | 说明 | 示例 |
|------|------|------|
| **方案A：API Key** | 请求头携带 `X-API-Key` | `X-API-Key: your-api-key` |
| **方案B：Bearer Token** | 请求头携带 `Authorization` | `Authorization: Bearer <token>` |
| **方案C：IP白名单** | 仅允许我方服务器IP访问 | 需数据方配置 |

### 1.3 通用请求约定

- **时间格式**：所有日期时间字段统一使用 `YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM:SS`，推荐前者。
- **空值处理**：缺失字段请使用 `null` 或空字符串 `""`，不要使用 `"nan"`、`"None"`、`"NULL"`、`"未提及"` 等字面量。
- **数值类型**：数值字段请直接返回数字类型，不要加引号变成字符串。
- **分页（如数据量大）**：
  - 请求参数：`page`（从1开始）、`page_size`（默认1000，最大10000）
  - 响应字段：`total`、`page`、`page_size`、`data`

### 1.4 通用响应格式

```json
{
  "code": 200,
  "message": "success",
  "total": 10000,
  "page": 1,
  "page_size": 1000,
  "data": [...]
}
```

### 1.5 通用错误码

| 状态码 | 含义 | 说明 |
|--------|------|------|
| 200 | 成功 | 正常返回 |
| 400 | 请求参数错误 | 缺少必填参数或参数格式非法 |
| 401 | 未授权 | API Key / Token 无效 |
| 403 | 禁止访问 | IP 不在白名单 |
| 404 | 接口不存在 | |
| 429 | 请求过于频繁 | 触发限流 |
| 500 | 服务器内部错误 | 数据方服务端异常 |

## 二、接口清单

本系统需要数据方提供 **7 类数据接口**，分别对应以下业务数据：

| 序号 | 接口名称 | 数据含义 | 我方用途 |
|------|----------|----------|----------|
| 1 | `入院信息查询` | 患者入院记录 | 患者画像、入院趋势、诊断统计、KG患者/就诊节点 |
| 2 | `出院信息查询` | 患者出院记录 | 住院天数分析、出院趋势、出院诊断、KG补充 |
| 3 | `检查信息查询` | 检查申请与报告 | 检查量统计、阳性率、KG检查节点 |
| 4 | `检验信息查询` | 检验申请与结果 | 检验量统计、异常指标、肿瘤标志物、KG检验节点 |
| 5 | `手术信息查询` | 手术记录 | 手术量统计、KG手术节点 |
| 6 | `医嘱信息查询` | 医嘱明细 | 用药模式、药品共现、KG药品/处方关系 |
| 7 | `数据字典查询` | 科室、药品、检查等维表 | 标准化映射辅助 |

> **注意**：若数据方可直接提供宽表或视图，也可协商合并接口，但字段必须完整。

## 三、接口详情

### 3.1 入院信息查询

- **接口地址**：`GET /api/v1/admission`
- **请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `start_date` | string | 否 | 入院日期开始，格式 `YYYY-MM-DD` |
| `end_date` | string | 否 | 入院日期结束，格式 `YYYY-MM-DD` |
| `patient_id` | string | 否 | 按患者ID精确查询 |
| `visit_id` | string | 否 | 按就诊流水号精确查询 |
| `page` | int | 否 | 页码，默认1 |
| `page_size` | int | 否 | 每页条数，默认1000，最大10000 |

- **响应字段（data数组元素）**：

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `patient_id` | string | **是** | 患者唯一标识 |
| `visit_id` | string | **是** | 就诊流水号，单次就诊唯一 |
| `medical_record_no` | string | 否 | 病案号 |

| `age` | number | **是** | 年龄，单位**天**；我方会换算为岁 |
| `gender` | string | 否 | 性别（男/女/未知） |
| `marital_status` | string | 否 | 婚姻状况 |
| `occupation` | string | 否 | 职业 |
| `admission_count` | int | 否 | 入院次数 |

## 四、数据关联规则

```
患者(patient_id)
  │
  ├─ 入院记录 ── visit_id ──┐
  ├─ 出院记录 ── visit_id ──┤
  ├─ 检查记录 ── visit_id ──┼── 共同构成一次就诊（Visit）
  ├─ 检验记录 ── visit_id ──┤
  ├─ 手术记录 ── visit_id ──┤
  └─ 医嘱记录 ── visit_id ──┘
```

### 4.1 关联字段一致性要求

| 字段 | 要求 |
|------|------|
| `patient_id` | 同一患者在所有表中必须完全相同（区分大小写） |
| `visit_id` | 同一就诊流水号必须对应同一患者，不同患者不能复用 |
| `medical_record_no` | 同一患者病案号建议保持一致，用于辅助校验 |
| `admission_date` | 入院表与出院表的同一 `visit_id` 入院日期应一致 |

---

## 五、数据质量要求

### 5.1 必填项完整性
- `patient_id`、`visit_id` 在所有表中不能为空。
- 时间类必填字段（`admission_date`、`exam_date`、`submit_time`、`surgery_start_time`）空值率应低于 5%。
- 诊断、药品、检查、检验、手术名称字段应使用院内标准化名称，避免自由文本差异过大。

### 5.2 值域规范

| 字段 | 建议值域 |
|------|----------|
| `gender` | `男`、`女`、`未知` |
| `is_drug` | `是`、`否`、`未知` |
| `result_hint` | `高`、`低`、`↑`、`↓`、`正常`、`偏高`、`偏低` 等 |
| `discharge_outcome` | 治愈、好转、未愈、死亡、转院、其他 |

### 5.3 时间格式
- 日期：`YYYY-MM-DD`，例如 `2024-03-15`
- 日期时间：`YYYY-MM-DD HH:MM:SS`，例如 `2024-03-15 09:30:00`
- 避免使用 `2024/03/15`、`15/03/2024`、`Mar-15-2024` 等非标格式

### 5.4 特殊字段清洗
- 诊断名称中不要包含 `"检查"`、`"待查"`、`"随访"`、`"体检"` 等非疾病词汇。
- 药品名称中避免包含 `"（中选）"`、`"【中选】"`、`"（国采）"` 等采购标记。
- 主诉文本末尾避免 `"，下一周期化疗"`、`"，入院治疗"`、`"，复查"` 等治疗后缀。

## 六、全量同步与增量同步建议

### 6.1 全量同步
- **场景**：首次对接、系统初始化、重建知识图谱
- **方式**：按时间范围分批次调用，建议每次 5000~10000 条
- **顺序**：入院 → 出院 → 检查 → 检验 → 手术 → 医嘱

### 6.2 增量同步
- **场景**：每日/每周定时更新
- **方式**：通过 `start_date` / `end_date` 参数按日期增量拉取
- **推荐频率**：每日凌晨同步前一日数据，周简报每周一同步上周数据
