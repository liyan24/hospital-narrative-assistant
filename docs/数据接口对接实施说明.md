# 数据接口对接实施说明

> 本文档面向医院叙事生成助手技术团队，说明如何将当前基于 Excel 的数据加载改造为通过数据方接口获取数据。

---

## 一、当前数据加载现状

当前系统通过 `pandas.read_excel()` 直接读取 `./data/` 目录下的 7 个 Excel 文件：

```
data/
├── 入院信息表_肿瘤血液科.xlsx
├── 出院信息表_肿瘤血液科.xlsx
├── 入出院交检查_肿瘤血液科.xlsx
├── 入出院交检验_肿瘤血液科.xlsx
├── 入出院交手术_肿瘤血液科.xlsx
├── 入出院交医嘱_肿瘤血液科1.xlsx
└── 入出院交医嘱_肿瘤血液科2.xlsx
```

消费这些 Excel 的核心服务：
- `services/data_analysis_service.py`
- `services/weekly_analysis_service.py`
- `services/kg_data_cleaner.py`（被 `knowledge_graph_service.py` 调用）

---

## 二、改造目标

将上述服务中的 `pd.read_excel(path)` 替换为调用数据方 HTTP API，支持：
1. **全量同步**：首次初始化或重建知识图谱时拉取全部历史数据
2. **增量同步**：日常按日期范围增量更新
3. **本地缓存**：接口数据缓存到本地，避免每次重复拉取
4. **降级能力**：网络异常时可回退到本地缓存数据

---

## 三、推荐架构

```
数据方 API
    │
    ▼
┌─────────────────────────┐
│  DataProviderClient     │  <-- 新增统一客户端
│  (认证、分页、重试、缓存)  │
└─────────────────────────┘
    │
    ├─► data_analysis_service    (统计报告)
    ├─► weekly_analysis_service  (周简报)
    └─► kg_data_cleaner          (知识图谱清洗)
```

## 四、具体改造步骤

### 4.1 新增 `database/data_provider_client.py`

封装统一的 HTTP 客户端，负责：
- 读取 `.env` 中的 `DATA_PROVIDER_BASE_URL`、`DATA_PROVIDER_API_KEY`
- 统一的认证头注入
- 自动分页拉取
- 失败重试（指数退避）
- 数据写入本地缓存（JSON/Parquet）

核心方法：

```python
class DataProviderClient:
    def fetch_admissions(self, start_date=None, end_date=None) -> pd.DataFrame
    def fetch_discharges(self, start_date=None, end_date=None) -> pd.DataFrame
    def fetch_exams(self, start_date=None, end_date=None) -> pd.DataFrame
    def fetch_labs(self, start_date=None, end_date=None) -> pd.DataFrame
    def fetch_surgeries(self, start_date=None, end_date=None) -> pd.DataFrame
    def fetch_orders(self, start_date=None, end_date=None) -> pd.DataFrame
    def fetch_dict(self, dict_type=None) -> pd.DataFrame
```

### 4.2 新增环境变量（`.env` / `config.py`）

```bash
# 数据方接口配置
DATA_PROVIDER_BASE_URL=https://data-provider.hospital.com
DATA_PROVIDER_API_KEY=your-api-key
DATA_PROVIDER_AUTH_TYPE=apikey  # apikey / bearer / none
DATA_PROVIDER_PAGE_SIZE=5000
DATA_PROVIDER_TIMEOUT=60
DATA_PROVIDER_CACHE_TTL_HOURS=24
```

```python
# config.py
class Settings(BaseSettings):

```

### 4.3 改造 `services/data_analysis_service.py`

当前代码（示例）：

```python
def load_admission_data(self):
    df = pd.read_excel(DATA_DIR / "入院信息表_肿瘤血液科.xlsx")
    ...
```

改造后：

```python
from database.data_provider_client import data_provider_client

def load_admission_data(self, start_date=None, end_date=None):
    df = data_provider_client.fetch_admissions(start_date, end_date)
    ...
```

注意：
- API 返回的字段名是英文下划线命名（如 `patient_id`），而原 Excel 是中文名（如 `患者ID`）
- 需要在 `DataProviderClient` 中做字段名映射，或者在 `load_*_data` 方法中直接处理映射后的 DataFrame

### 4.4 改造 `services/weekly_analysis_service.py`

与 data_analysis_service 类似，复用同一套 `load_*_data` 方法：

```python
def run_weekly_analysis(self, dt):
    week_start, week_end = self._get_week_range(dt)
    df_admission = data_provider_client.fetch_admissions(week_start, week_end)
    ...
```

### 4.5 改造 `services/kg_data_cleaner.py`

当前 `run_all()` 直接读取 Excel：

```python
def run_all(self, use_cache=True):
    ...
    df_admission = pd.read_excel(...)
    df_discharge = pd.read_excel(...)
    ...
```

改造后：

```python
def run_all(self, use_cache=True, start_date=None, end_date=None):
    ...
    df_admission = data_provider_client.fetch_admissions(start_date, end_date)
    df_discharge = data_provider_client.fetch_discharges(start_date, end_date)
    ...
```

注意：
- 知识图谱构建通常需要全量数据，首次调用 `start_date` 可设为最早入院日期
- 增量更新时，可按日期范围拉取，再通过 Neo4j 的 `MERGE` 机制保证幂等性

### 4.6 字段名映射

由于接口文档中定义了英文字段名，而原代码使用中文字段名，需要建立映射表。

推荐方式：在 `DataProviderClient.fetch_*` 方法返回 DataFrame 前，将英文列名映射为原中文列名，保证下游服务代码最小改动。

示例映射：

```python
ADMISSION_COLUMN_MAP = {
    "patient_id": "患者ID",
    "visit_id": "就诊流水号",
    "medical_record_no": "病案号",
    "admission_date": "入院日期",
    "age": "年龄",
    "gender": "性别",
    "marital_status": "婚姻",
    "occupation": "职业",
    "admission_count": "入院次数",
    "chief_complaint": "主诉",
    "present_illness": "现病史",
    "allergy_history": "过敏史",
    "admission_record": "入院记录",
    "diagnosis_western_1": "入院西医主要诊断1",
    ...
}
```

### 4.7 本地缓存策略

为了避免每次重启服务都重新拉取接口数据，建议：

| 层级 | 文件路径 | 说明 |
|------|----------|------|
| 原始数据缓存 | `./data/cache/api/admissions_YYYYMMDD.json` | 按日期范围缓存接口原始响应 |
| 清洗后数据缓存 | `./data/kg_cleaned/cleaned_data.json` | 知识图谱构建缓存，已存在 |
| 分析结果缓存 | `./data/json_store/analysis_latest.json` | 分析结果缓存，已存在 |

缓存失效策略：
- 每日凌晨主动触发全量同步任务
- 用户手动点击"刷新数据"按钮时强制绕过缓存
- `DATA_PROVIDER_CACHE_TTL_HOURS` 控制缓存有效期

## 五、新增/改造的后端 API

为了让前端可以控制数据刷新，建议新增以下 API：

### 5.1 数据同步状态查询

```
GET /api/data/sync/status
```

响应：

```json
{
  "status": "ok",
  "last_sync_at": "2024-06-08 02:00:00",
  "last_sync_type": "incremental",
  "record_counts": {
    "admission": 13743,
    "discharge": 13743,
    "exam": 89234,
    "lab": 456789,
    "surgery": 3456,
    "order": 1234567
  },
  "cache_valid": true
}
```

### 5.2 手动触发数据同步

```
POST /api/data/sync/trigger
Body: {
  "sync_type": "full" | "incremental",
  "start_date": "2024-01-01",
  "end_date": "2024-12-31"
}
```

响应：

```json
{
  "status": "ok",
  "sync_id": "sync_20240608_020000",
  "message": "同步任务已启动"
}
```

### 5.3 改造知识图谱构建接口

当前：


改造后支持按日期范围构建：

```

  "clear": false,

  "end_date": "2024-12-31",
  "use_cache": true

```

## 七、风险与注意事项

1. **字段缺失兼容**：原代码对 Excel 字段缺失有大量容错（`if field in df.columns`），接口改造后需保持同样兼容性。
2. **大表分页**：医嘱表可能上百万条，必须严格分页，不能一次性返回全量。
3. **时间解析**：接口返回的时间字段格式必须统一，否则 `pd.to_datetime(..., errors='coerce')` 会丢失大量记录。
4. **网络超时**：大表全量同步可能需要数分钟，需设置合理的 `timeout` 和重试机制。
5. **数据幂等性**：知识图谱使用 Neo4j `MERGE` 保证重复构建不重复生成节点，但仍需注意关系属性更新。
6. **字段命名**：接口文档采用英文下划线命名，内部代码仍使用中文列名，映射层需维护好对应关系。

## 九、推荐的最小可行改造（MVP）

如果工期紧张，推荐先做最小可行改造：

1. 开发 `DataProviderClient`，仅支持全量同步
2. 修改 `kg_data_cleaner.py`，在构建知识图谱前调用接口拉取全部数据并保存为 Excel 到 `./data/` 目录
3. 其余 `data_analysis_service`、`weekly_analysis_service` **暂不改动**，继续使用本地 Excel

这样可以在不改动大量统计逻辑的前提下，先解决知识图谱的数据源问题。
