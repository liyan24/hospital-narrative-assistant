# 医院叙事生成助手 — 知识图谱说明文档

> 版本：v1.0  
> 本文档描述医院叙事生成助手项目中 Neo4j 医疗知识图谱的完整结构，包括节点类型、关系类型、属性定义、数据来源及构建流程。

---

## 一、图谱概述

### 1.1 设计目标

基于肿瘤血液科真实脱敏数据，构建覆盖 **患者-就诊-疾病-药品-检查-检验-手术-科室-主诉** 的医疗知识图谱，支撑：
- 患者个体就诊故事线生成
- 疾病诊疗路径挖掘
- 合并症与用药模式分析
- 相似患者推荐
- KG+RAG 智能问答
- 知识图谱可视化探索

### 1.2 技术架构

| 项目 | 说明 |
|------|------|
| 图数据库 | Neo4j |
| 连接协议 | Bolt (`bolt://localhost:7687`) |
| 配置位置 | `.env` / `config.py`（`NEO4J_URI`、`NEO4J_USER`、`NEO4J_PASSWORD`） |
| 构建入口 | `POST /api/kg/build` 或 Streamlit 页面 **⚙️ 知识图谱管理** |
| 清洗输出 | `data/kg_cleaned/cleaned_data.json` |

### 1.3 图谱规模

| 指标 | 数量 |
|------|------|
| 节点总数 | 约 31,694 |
| 关系总数 | 约 788,119 |
| 节点标签数 | 9 |
| 关系类型数 | 9 |

## 三、节点属性详情

### 3.1 Patient（患者）

| 属性 | 类型 | 含义 | 来源字段 |
|------|------|------|----------|
| `patient_id` | `string` | 患者唯一标识（主键） | `患者ID` |
| `medical_record_no` | `string` | 病案号 | `病案号` |
| `age` | `int` | 年龄（岁） | `年龄`（原单位为天时换算） |
| `marital_status` | `string` | 婚姻状况 | `婚姻` |
| `occupation` | `string` | 职业 | `职业` |
| `allergy_history` | `string` | 过敏史 | `过敏史` |

> 注：当前 `kg_data_cleaner.py` 未抽取 `gender` 字段，图谱中实际不存在性别属性。

### 3.2 Visit（就诊）

| 属性 | 类型 | 含义 | 来源字段 |
|------|------|------|----------|
| `visit_id` | `string` | 就诊流水号（主键） | `就诊流水号` |
| `patient_id` | `string` | 所属患者 ID | `患者ID` |
| `admission_date` | `string` | 入院日期 `YYYY-MM-DD` | `入院日期` |
| `discharge_date` | `string` | 出院日期 | `出院日期` |
| `length_of_stay` | `int` | 住院天数 | `住院天数` |
| `chief_complaint` | `string` | 主诉（清洗后） | `主诉` |

### 3.3 Disease（疾病/中医证型）

| 属性 | 类型 | 含义 | 来源/计算方式 |
|------|------|------|---------------|
| `name` | `string` | 复合键：`{归一化名称}::{类型}` | `display_name` + `type` 拼接 |
| `display_name` | `string` | 归一化后的疾病/证型显示名称 | 入院/出院诊断字段 |
| `type` | `string` | 诊断类型 | `western` / `tcm` / `tcm_syndrome` |
| `category` | `string` | 出现场景 | `admission` / `discharge` / `admission,discharge` |
| `frequency` | `int` | 出现频次 | 统计得到 |

**疾病归一化规则**：
- 过滤非疾病关键词：`检查`、`待查`、`随访`、`体检` 等
- 同义词映射：`高血压病` → `高血压`、`脑梗塞` → `脑梗死`、`肺癌` → `肺恶性肿瘤`
- 组合诊断拆分：`肺积 痰瘀互结证` → `肺积` + `痰瘀互结证`
- 类型标记：西医诊断附加 `::western`，中医病名附加 `::tcm`，证型附加 `::tcm_syndrome`

### 3.4 ChiefComplaint（主诉）

| 属性 | 类型 | 含义 | 来源字段 |
|------|------|------|----------|
| `name` | `string` | 清洗后的主诉文本（主键） | `主诉` |

**清洗规则**：去除治疗后缀（如 `，下一周期化疗`、`，入院治疗`、`，复查`）及句末标点。

| `category` | `string` | 标准大类名称 | `标准大类名称` |
| `body_part` | `string` | 检查部位 | `检查部位` |

### 3.6 LabItem（检验）

| 属性 | 类型 | 含义 | 来源字段 |
|------|------|------|----------|

| `unit` | `string` | 单位 | `检验项目单位` |
| `reference_range` | `string` | 参考范围 | `参考范围` |

### 3.7 Drug（药品）

| 属性 | 类型 | 含义 | 来源字段 |
|------|------|------|----------|
| `name` | `string` | 清洗后的药品名称（主键） | `医嘱项目名称` |

**清洗规则**：

## 四、关系类型（Relationship Types）

| 关系类型 | 方向 | 含义 | 属性 |
|----------|------|------|------|
| `HAS_VISIT` | `Patient → Visit` | 患者拥有就诊 | 无 |
| `DIAGNOSED_WITH` | `Visit → Disease` | 就诊诊断 | `diagnosis_type`, `is_main` |
| `CHIEF_COMPLAINT` | `Visit → ChiefComplaint` | 就诊主诉 | 无 |
| `PERFORMED_EXAM` | `Visit → Exam` | 执行检查 | `exam_date`, `report_date`, `description`, `diagnosis` |
| `HAS_LAB_RESULT` | `Visit → LabItem` | 检验结果 | `value`, `unit`, `reference_range`, `abnormal_flag`, `hint` |
| `PRESCRIBED` | `Visit → Drug` | 处方/用药 | `dosage`, `dosage_unit`, `frequency`, `route`, `start_date`, `end_date`, `order_category` |
| `UNDERWENT` | `Visit → Surgery` | 接受手术 | `start_date`, `end_date`, `description` |
| `IN_DEPARTMENT` | `Visit → Department` | 就诊所属科室 | 无 |
| `TREATS` | `Drug → Disease` / `Surgery → Disease` | 治疗关系（衍生） | `evidence` |

### 4.1 关系属性详情

#### DIAGNOSED_WITH（就诊-诊断）

| 属性 | 类型 | 含义 | 来源 |
|------|------|------|------|
| `diagnosis_type` | `string` | `admission` 或 `discharge` | 诊断来源表 |
| `is_main` | `bool` | 是否主要诊断 | 第 1 条诊断为 `true` |

#### PERFORMED_EXAM（就诊-检查）

| 属性 | 类型 | 含义 | 来源字段 |
|------|------|------|----------|
| `exam_date` | `string` | 检查日期 | `检查日期` |
| `report_date` | `string` | 报告日期 | `报告日期` |
| `description` | `string` | 检查描述 | `描述` |
| `diagnosis` | `string` | 检查诊断 | `诊断` |

#### HAS_LAB_RESULT（就诊-检验）

| 属性 | 类型 | 含义 | 来源字段 |
|------|------|------|----------|
| `value` | `float` | 检验结果数值 | `检验项目结果` |
| `unit` | `string` | 单位 | `检验项目单位` |
| `reference_range` | `string` | 参考范围 | `参考范围` |
| `abnormal_flag` | `bool` | 是否异常 | 由 `检验项目提示` 推断 |
| `hint` | `string` | 原始提示 | `检验项目提示` |

#### PRESCRIBED（就诊-药品）

| 属性 | 类型 | 含义 | 来源字段 |
|------|------|------|----------|
| `dosage` | `string` | 单次剂量 | `单次剂量` |
| `dosage_unit` | `string` | 单次剂量单位 | `单次剂量单位` |
| `frequency` | `string` | 使用频率 | `使用频率名称` |
| `route` | `string` | 给药途径 | `给药途径` |
| `start_date` | `string` | 医嘱开始时间 | `医嘱开始时间` |
| `end_date` | `string` | 医嘱停止时间 | `医嘱停止时间` |
| `order_category` | `string` | 医嘱类别 | `医嘱类别` |

#### UNDERWENT（就诊-手术）

| 属性 | 类型 | 含义 | 来源字段 |
|------|------|------|----------|
| `start_date` | `string` | 手术开始时间 | `手术开始时间` |
| `end_date` | `string` | 手术结束时间 | `手术结束时间` |
| `description` | `string` | 手术过程描述 | `手术过程描述` |

#### TREATS（药品/手术-疾病，衍生关系）

通过同一次就诊中的药品/手术与出院诊断共现推导：

```cypher
MATCH (v:Visit)-[:PRESCRIBED]->(d:Drug)
MATCH (v)-[:DIAGNOSED_WITH {diagnosis_type: 'discharge'}]->(dis:Disease)
MERGE (d)-[r:TREATS]->(dis)
SET r.evidence = 'same_visit_prescription'
```

| 属性 | 类型 | 含义 |
|------|------|------|
| `evidence` | `string` | `same_visit_prescription` 或 `same_visit_surgery` |

## 七、知识图谱构建流程

```
┌──────────────────────┐
│   Excel 原始数据      │
└──────────┬───────────┘
           ▼
┌──────────────────────────────────┐
│ services/kg_data_cleaner.py      │
│ · 读取 7 个 Excel 文件            │
│ · 字段清洗、标准化、过滤           │
│ · 构建节点与关系 JSON              │
│ · 输出 data/kg_cleaned/           │
│   cleaned_data.json               │
└──────────┬───────────────────────┘
           ▼
┌──────────────────────────────────┐
│ services/knowledge_graph_service.py│
│ 1. setup_schema()                │
│    创建约束与索引                  │
│ 2. import_*()                    │
│    批量导入 9 类节点               │
│ 3. import_*_rels()               │
│    批量导入 8 类基础关系            │
│ 4. build_treatment_rels()        │
│    衍生 TREATS 关系                │
└──────────┬───────────────────────┘
           ▼
┌──────────────────────┐
│    Neo4j 知识图谱     │
└──────────────────────┘
```

### 7.1 详细构建步骤

1. **连接测试**：验证 Neo4j 是否可连接
2. **清空图谱（可选）**：`MATCH (n) DETACH DELETE n`
3. **创建 Schema**：
   - 唯一性约束：Patient、Visit、ChiefComplaint、Exam、LabItem、Drug、Surgery、Department
   - 索引：Patient.medical_record_no、Visit.admission_date、Disease.name、Disease.type
4. **数据清洗/加载缓存**：`KGDataCleaner.run_all(use_cache=True)`
5. **导入节点**：按 `batch_size=5000` 分批 `MERGE`
6. **导入关系**：按 `batch_size=5000` 分批 `MERGE`
7. **构建衍生关系 `TREATS`**
8. **打印统计信息**

## 八、Schema 定义

### 8.1 唯一性约束

```cypher
CREATE CONSTRAINT patient_id IF NOT EXISTS
  FOR (p:Patient) REQUIRE p.patient_id IS UNIQUE

CREATE CONSTRAINT visit_id IF NOT EXISTS
  FOR (v:Visit) REQUIRE v.visit_id IS UNIQUE

CREATE CONSTRAINT complaint_name IF NOT EXISTS
  FOR (c:ChiefComplaint) REQUIRE c.name IS UNIQUE

CREATE CONSTRAINT exam_name IF NOT EXISTS
  FOR (e:Exam) REQUIRE e.name IS UNIQUE

CREATE CONSTRAINT labitem_name IF NOT EXISTS
  FOR (l:LabItem) REQUIRE l.name IS UNIQUE

CREATE CONSTRAINT drug_name IF NOT EXISTS
  FOR (dr:Drug) REQUIRE dr.name IS UNIQUE

CREATE CONSTRAINT surgery_name IF NOT EXISTS
  FOR (su:Surgery) REQUIRE su.name IS UNIQUE

CREATE CONSTRAINT dept_name IF NOT EXISTS
  FOR (de:Department) REQUIRE de.name IS UNIQUE
```

### 8.2 索引

```cypher
CREATE INDEX patient_mrn IF NOT EXISTS
  FOR (p:Patient) ON (p.medical_record_no)

CREATE INDEX visit_admission_date IF NOT EXISTS
  FOR (v:Visit) ON (v.admission_date)

CREATE INDEX disease_name IF NOT EXISTS
  FOR (d:Disease) ON (d.name)

CREATE INDEX disease_type IF NOT EXISTS
  FOR (d:Disease) ON (d.type)
```

### 8.3 主键说明

| 节点标签 | 主键属性 | 是否唯一约束 |
|----------|----------|--------------|
| `Patient` | `patient_id` | 是 |
| `Visit` | `visit_id` | 是 |
| `Disease` | `name` | 否（仅索引，依赖清洗逻辑保证唯一） |
| `ChiefComplaint` | `name` | 是 |
| `Exam` | `name` | 是 |
| `LabItem` | `name` | 是 |
| `Drug` | `name` | 是 |
| `Surgery` | `name` | 是 |
| `Department` | `name` | 是 |

> 建议：为 `Disease.name` 追加 `UNIQUE` 约束以强化数据一致性。

## 九、上层服务使用场景

| 服务/功能 | 主要 Cypher 查询模式 | 用途 |
|-----------|----------------------|------|
| 患者故事线 | `Patient → HAS_VISIT → Visit → 所有关系` | 生成个体患者就诊时间线 |
| 诊疗路径 | `Disease → DIAGNOSED_WITH ← Visit → PRESCRIBED/UNDERWENT/PERFORMED_EXAM/HAS_LAB_RESULT` | 挖掘疾病典型诊疗模式 |
| 合并症分析 | `Disease ← DIAGNOSED_WITH ← Visit → DIAGNOSED_WITH → Disease` | 发现疾病共现网络 |
| 用药模式 | `Visit → PRESCRIBED → Drug` 共现统计 | 分析药品联用规律 |
| 再入院分析 | `Patient → HAS_VISIT → Visit` 按时间排序 | 识别多次就诊患者 |
| 相似患者 | 共同邻居算法（Jaccard） | 推荐相似病例 |
| RAG 问答 | 患者时间线/疾病路径/用药模式子图 | 基于真实图谱回答问题 |
| 图谱可视化 | 指定起始节点的子图查询 | ECharts 力导向图展示 |

## 十、关键注意事项

1. **Disease 未设置唯一约束**：当前仅通过 `MERGE` 和清洗逻辑保证 `name` 唯一，建议补加 `UNIQUE` 约束。
2. **Patient.gender 未导入**：数据接口文档中包含性别字段，但当前清洗逻辑未抽取，导致部分服务查询 `p.gender` 时返回空值。
3. **日期格式**：清洗后统一为 `YYYY-MM-DD` 字符串，时间字段仅保留日期部分。
4. **清洗缓存较大**：`cleaned_data.json` 约 338 MB，全量构建时建议确认 Neo4j 内存配置。
5. **关系去重**：节点导入全局去重，关系按 `(from_key, to_key)` 去重；`TREATS` 按 `(Drug/Surgery, Disease)` 去重。
6. **数据质量依赖**：疾病归一化、药品清洗、时间解析的准确性直接影响图谱质量和上层分析结果。
